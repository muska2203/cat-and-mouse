# Идеи и бэклог

Сюда складываем идеи по мере появления. Единый бэклог отсортирован по приоритету: **высокий** -> **средний** -> **низкий**.

---

## Единый бэклог

### Восстановление HP/MP через скиллы
- **Приоритет:** высокий
- В README ранее было упоминание восстановления HP/MP от скиллов, но по целевой механике восстановление должно идти только через расходники.
- Задача: переработать/убрать восстанавливающие скиллы и держать документацию в этом же правиле.

### Расширить скиллы посохов
- **Приоритет:** высокий
- Текущая механика уже корректная: скиллы предмета доступны только при экипированном источнике.
- Идея: расширить контент посохов (больше вариантов активных скиллов/синергий), а не чинить условие активации.

### Урон врагам (сложность)
- **Приоритет:** высокий
- Поднять урон у врагов, чтобы бой ощущался чуть сложнее.

### Лут на земле при генерации уровня
- **Приоритет:** средний
- В концепте заявлен как объект уровня, но сейчас на старте уровня лут обычно не раскладывается (чаще появляется из сундуков).
- Уточнение: формулировку «размещается на уровне/этаже» трактуем как генерацию объектов для конкретного уровня забега.
- Задача: либо добавить стартовый спавн лута, либо уточнить формулировку концепта.

### Ловушки и временные зоны как часть генерации уровня
- **Приоритет:** средний
- В концепте описаны как элементы уровня, но сейчас чаще появляются от действий игрока (расходники/эффекты), а не заранее.
- Уточнение: «размещается на уровне/этаже» относится к генерации объектов на каждом уровне забега.
- Задача: решить, нужны ли прегенерированные ловушки/облака в самом уровне.

### Боссы в итоговом экране без отдельной системы боссов
- **Приоритет:** средний
- На экране итогов есть секция «Побежденные боссы», но отдельной босс-механики в боевой/спавн-логике пока нет.
- Решение по статусу: оставить блок, но явно пометить как «в разработке» до реализации боссов.

### Геймплей через «интеллект»
- **Приоритет:** средний
- Проработать геймплейные особенности с опорой на ИИ (подсказки, процедурные события, поведение врагов, генерация контента).
- При постановке в работу фиксировать конкретный фокус, чтобы не распылять задачу.

### Выбор сложности при старте забега
- **Приоритет:** средний
- В концепте есть пункт «сложность (в разработке)», но в текущем экране создания персонажа выбор сложности отсутствует.
- Решение по документации: оставить в README с явной пометкой «в разработке» до появления UI.
- Задача: добавить явный выбор сложности в создании персонажа, когда пункт перейдет в реализацию.

### Миникарта
- **Приоритет:** низкий
- Краткая карта уровня (обзор лабиринта, цель, игрок).

### Масштаб игры
- **Приоритет:** низкий
- Доработать масштабирование интерфейса: сейчас есть базовый zoom/подстройка размера тайла канваса, но нет отдельной настройки масштаба UI-панелей и типографики под разные DPI.
