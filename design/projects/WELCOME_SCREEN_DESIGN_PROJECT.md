# Дизайн-проект: стартовая страница выбора и настройки персонажа

Документ задаёт целевой UI для стартового экрана (до начала забега) в стилистике `design/main_concept.png` и текущего макета `design/impl`.

Важно: это новый дизайн с нуля для `design`, без опоры на реализованный UI игры.

---

## 1. Цель экрана

Экран должен позволять игроку до старта:

- выбрать портрет героя;
- распределить стартовые очки по базовым характеристикам;
- видеть итоговые боевые/служебные характеристики, включая итоговые HP и ману;
- выбрать стартовые предметы (по одному в каждый слот экипировки);
- открыть подсказки по игре и Devlog;
- нажать кнопку старта забега.

---

## 2. Визуальный стиль

- Единый стиль с `design/impl`: дерево, бронзово-золотые рамки, заклепки, тёплая палитра, serif-заголовки и sans-текст.
- Та же «система панелей»: `cm-panel`-подход, единый ритм отступов и заголовков.
- Элементы взаимодействия (кнопки, слоты, переключатели) визуально совместимы с текущим дизайн-макетом забега.
- Язык UI: русский.

---

## 3. Компоновка (десктоп приоритет, ~1200px+)

Рекомендуемая структура: 3 колонки, как у экрана забега.

1. **Левая колонка (герой и статы)**
   - Портрет героя в круглой рамке.
   - Круглый бейдж уровня (для стартового экрана обычно `1`).
   - Блок распределения характеристик.
   - Блок итоговых параметров (включая HP и мана).

2. **Центральная колонка (портреты и предпросмотр)**
   - Панель выбора портрета (галерея карточек/аватаров).
   - Крупный предпросмотр выбранного героя.
   - Краткий «паспорт» выбранного варианта (имя шаблона/описание — опционально).

3. **Правая колонка (экипировка и справка)**
   - Выбор стартовых предметов по слотам: оружие, броня, амулет.
   - Кнопки/панели: «Подсказки», «Devlog».
   - Главная CTA-кнопка: «Начать забег».

Правило баланса ширин для `design/impl/welcome.html`:

- Левая и правая колонки делаются одинаковой ширины (симметрия боковых панелей).
- Центральная колонка забирает остаток пространства.
- Макет не растягивается на весь экран: рабочая сцена ограничивается по ширине и высоте, без лишних пустот по краям.

---

## 4. Блоки и поведение

## 4.1. Выбор портрета героя

- Отображается сетка доступных портретов.
- В каждый момент выбран ровно один портрет.
- Выбранный портрет имеет явное состояние `active` (рамка/свечение/маркер).
- Клик по карточке меняет выбранный портрет и обновляет крупный предпросмотр.

## 4.2. Распределение характеристик

Базовые характеристики для ручного распределения:

- Сила
- Интеллект
- Ловкость
- Удача

В `design/impl/welcome.html` характеристики показываются единым списком:

- сверху — базовые (распределяемые) характеристики;
- ниже — производные/боевые (например `Крит шанс`, `Крит x`) без отдельного блока «Боевые параметры».

Требования:

- У каждой строки: название, значение, кнопки `-` и `+` (или только `+` при фиксированной базе).
- Отображается счётчик «Свободные очки».
- Нельзя уйти ниже стартового минимума.
- Нельзя превысить лимит распределения.
- При каждом изменении мгновенно пересчитываются итоговые параметры.
- Для нераспределяемых строк (без `+/-`) значение выравнивается по правому краю строки.

## 4.3. Остальные характеристики и итог ресурсов

Должны явно присутствовать:

- Крит шанс
- Крит x (или «Крит множ.»)
- Доп. параметры по модели игры (например, обзор/другие derived-поля, если включены в стартовый экран)

Отдельно и заметно:

- **Итоговый HP** (`текущее/максимум` на старте или минимум `HP max`)
- **Итоговая мана** (`текущее/максимум` на старте или минимум `мана max`)

Рекомендация:

- показать HP/ману в виде мини-полос (как на экране забега) + числовые значения.

## 4.4. Выбор стартовых предметов

Слоты выбора:

- Оружие — выбрать 1 предмет
- Броня — выбрать 1 предмет
- Амулет — выбрать 1 предмет

Требования:

- Для каждого слота показывается список/лента доступных стартовых вариантов.
- В пределах одного слота активен только один выбор.
- Выбранный предмет подсвечивается и отображается в итоговом слоте экипировки.
- В карточке предмета: иконка, название, краткий бонус/эффект.

## 4.5. Подсказки и Devlog

- На экране есть явные элементы для открытия:
  - «Подсказки по игре»
  - «Devlog»
- Формат открытия: модальное окно или выдвижная панель (определить на этапе реализации макета).
- Доступ без смены страницы, чтобы не терять сделанные выборы.

## 4.6. Кнопка старта

- Основная кнопка: «Начать забег».
- Кнопка активна только при валидной конфигурации:
  - выбран портрет;
  - в каждом слоте экипировки выбран 1 стартовый предмет;
  - очки характеристик распределены допустимо.

---

## 5. Состояния UI

Обязательные визуальные состояния:

- `default`, `hover`, `active`, `disabled` для кнопок и карточек выбора.
- `selected` для портрета и предмета.
- `blocked` для недоступных действий (`+` без очков, `-` при минимуме и т.д.).
- Пустые/инициальные состояния (до выбора портрета и предметов).

---

## 6. Адаптивность

- При узкой ширине экрана колонки складываются вертикально.
- Приоритет сверху вниз:
  1) выбор портрета и статы,
  2) выбор стартовой экипировки,
  3) подсказки/devlog/кнопка старта.
- Критичные элементы (кнопка старта, свободные очки, HP/мана, выбранные слоты) остаются заметными без глубокой прокрутки.

---

## 7. Доступность и UX-минимум

- Поддержка клавиатуры для всех интерактивных контролов (focus-visible, Enter/Space).
- Контраст текста на деревянных фонах не ниже читаемого уровня.
- У иконок и декоративных элементов есть `aria-hidden`, у смысловых — текстовые подписи.
- Тултипы у длинных названий предметов/пояснений.

---

## 8. Что делаем следующим шагом

Следующим этапом для `design/impl`:

1. Создать отдельный макет-файл стартовой страницы (например, `design/impl/welcome.html`).
2. Добавить/переиспользовать стили в духе текущего `game-screen.css` (желательно вынести общие токены в общий CSS).
3. Заполнить тестовыми данными:
   - 6–10 портретов,
   - стартовые наборы предметов на каждый слот,
   - пример распределения очков и live-пересчёта итогов (допустимо демонстрационно).

---

## 9. Критерии готовности дизайн-макета страницы

Макет считается готовым, если:

- визуально соответствует теме концепта и текущей странице забега;
- покрывает все функциональные блоки из этого документа;
- демонстрирует все ключевые состояния выбора;
- не использует код реализованного игрового UI вне папки `design`.

## 10. Зафиксированные правки (согласовано)

- Создан статический макет страницы: `design/impl/welcome.html`.
- Добавлены стили страницы: `design/impl/welcome.css` (на базе визуальной системы `game-screen.css`).
- Сцена экрана сделана компактной (не full-screen), с ограничением рабочей области.
- Ширина правой колонки приведена к ширине левой (симметричные боковые панели).
- Разделение на отдельные блоки «основные» и «боевые» характеристики убрано: используется единый список.
- У характеристик без распределения (`Крит шанс`, `Крит x`) значение фиксируется по правому краю, без кнопок `+/-`.
- Для выбора стартовых предметов внедрены всплывающие карточки описания (hover/focus): заголовок предмета + список характеристик/эффектов.
- Общий стандарт тултипов вынесен в `design/TOOLTIPS_DESIGN_PROJECT.md`.
